## New
- **Animated covers on the big cover in portrait** (Settings → Now Playing → Big cover). The switch that put a Spotify Canvas there is now a list like the landscape cover stage: Spotify Canvas, Animated cover and Cover art, and a song gets the first one it has. A cover fills the top of the screen and melts into the background, as in Apple Music, with the song under it and the controls kept up. Canvas then Animated cover by default; if you had the Canvas switched off, nothing is picked

## Changed
- **The Chinese lyrics sources say they also ask Apple's iTunes search.** When Kugou, QQ Music, Kuwo or NetEase don't find a song by its name, its title and artist go to Apple's iTunes search to find its name in Japan, Korea, Taiwan or Hong Kong. Their notices now say so
- The landscape setting is now called "Cover stage (landscape)"
- While the cover stage or the big cover shows the record's cover, the Canvas background steps aside, so the cover melts into its own colours

## Fixed
- **The widget no longer redraws everything every few seconds** while music plays, which used battery for nothing
- **A widget placed before notification access was given** now starts working once it is, instead of asking for access until the app restarted
- **Widget lyrics squeezed into a few words on some Samsung phones** ([#44](https://github.com/spicylyrics/mobile/issues/44)). This fixes the most likely cause; if yours still looks wrong, the extra logs now show what the phone reports
- **Opening a file picker** (backing up or restoring settings, a font, a TTML, the lyrics folder) no longer shrinks the lyrics into the floating window and loses the file
- **Lyrics from LRCLIB, Unison and RMM with word timing** showed stamps like `<00:01.50>` as words. They now keep their word timing
- **LRC with a translation under each line** (two lines on one timestamp) no longer flashes the original past and shows the translation as the sung line
- Some synced lyrics showed "couldn't show these lyrics" instead of trying the next source
- **Switching to a player that doesn't say what's playing** no longer keeps the last song's lyrics on screen
- **A seek to the end of a song** no longer stalls the next song's lyrics or shows the "can't seek" notice to Spotify Premium users
- **A song that plays into the next one** no longer starts the next song's lyrics at its end
- A player reporting itself playing at speed 0 no longer freezes the lyrics
- **A source that timed out or turned a song away** is asked again the next time the song comes up, instead of staying out for the session
- **Scrolling the lyrics by hand** is no longer undone by turning the phone, changing the text size or a translation arriving, and static lyrics no longer jump to the top
- On Android 13 and later, the setup screen explains how to allow notification access when Android blocks it for apps installed from a downloaded APK
- Restoring an older settings backup no longer brings the setup screen back
- A crash in the queue when a player lists the same song twice

## Known limitations
- The Samsung widget fix ([#44](https://github.com/spicylyrics/mobile/issues/44), [#42](https://github.com/spicylyrics/mobile/issues/42)) hasn't been confirmed on a Samsung phone yet. Tablet widgets in landscape may still look small
